# Testing Context

Overview of the testing strategy for the RedCyberFox OT SOC platform.

## Test Categories
- **Standard Tests**: Unit tests covering core logic, parsing, and data structures.
- **Storage Tests**: Tests verifying SQLite interactions, storage limits, atomicity, quota enforcement, and identity migration (e.g. legacy identity ignored when DB exists).
- **Forwarder Tests**: Tests validating the `HTTP POST -> 202 -> remove` flow, including exponential backoff, 400 DLQ routing, and transient error retries.
- **Offline Integration Tests**: End-to-end tests validating that the agent can queue events locally while offline and successfully flush them sequentially when the network is restored.
- **Lost-Response/Idempotency Tests**: Tests simulating a dropped HTTP response after a successful server ingest, ensuring that the duplicate retry is handled gracefully by the server using `event_id`.
- **Measurement Report & Safety Tests (`agent/internal/resourcereport`)**: Unit tests covering duration/interval range validation, sample limits, output byte limits, refusal of overwrite (`O_EXCL`), persistence file conflict rejection (DB/WAL/SHM/identity/config/spill), watched path conflict rejection, visible write error handling, null metric preservation, and timer/signal shutdown overlap.
- **Shared Request Isolation Tests (`dashboard/src/request_isolation.test.mjs`)**: Direct exercise of production `fetchTenantData` request logic verifying generation counter advances, abort signal propagation, and discarding delayed responses from previous tenants upon rapid switching.
- **Workload Demonstration Tests (`agent/internal/integration/workload_demonstration_test.go`)**: Production pipeline verification of harmless bounded events, metadata IOC rule matching (`LOCAL-IOC-EXEC-001`), derived finding generation with deterministic UUIDv5 identity, explicit evidence event ID linkage, and durable presence after clean shutdown.
- **Windows Workload Measurement Suite (`agent/internal/integration/workload_reports_test.go`)**: End-to-end multi-scenario execution of freshly compiled `endpoint.exe` in isolated workspaces (`t.TempDir()`), validating binary VCS provenance (`vcs.revision`, `vcs.modified`, `toolchain`, SHA-256) via `go version -m` against clean git state (`dirty: false`). Source stability is verified across three boundaries (`pre-compilation`, `post-compilation`, `post-workload`). Every external command is strictly governed by explicit timeout contexts via `RunBoundedCommand` and `StartManagedSubprocess` with bounded buffer stdout/stderr capture and truthful exit code reflection (`*int`, `nil` on launch failure). Canonical reports are protected from overwriting; runs export exclusively to unique run directories alongside `commands.log` and `provenance.json`. Active testing finalizer (`RegisterTestingFinalizer`) retains complete diagnostic manifests and partial reports if any scenario or boundary fails, preventing failed runs from exporting accepted evidence.
- **Binary Provenance, Subprocess Lifecycle & Diagnostic Retention Tests (`agent/internal/integration/provenance_test.go`, `provenance_windows_test.go`, `provenance_unix_test.go`)**: Unit tests covering `ParseBinaryProvenanceOutput` handling Windows and POSIX absolute executable paths, strict rejection of missing fields (toolchain, revision, modified), `WriteEvidenceExclusive` overwrite refusal, `ExportEvidenceRun` refusing overwrite and preserving unrelated files, `CheckSourceBoundary` stability verification, output capture, unwrapping wrapped `*exec.ExitError` codes via `errors.As`, launch failure exit code semantics (`nil`), timeout deadline handling, output buffer truncation markers, diagnostic write failure and locked/unreadable partial-report error propagation (`TestDiagnosticErrors_WriteAndCopyFailure`), and persistent failure diagnostic retention (`TestDiagnosticRetention_FailedAndInvalidRuns`) ensuring child qualification failures leave complete diagnostic manifests and logs outside child tempdirs after testing cleanup runs. Platform-specific unreadable file fixtures are build-tagged (`provenance_windows_test.go` Win32 exclusive lock vs `provenance_unix_test.go` broken symlink deterministic under root) so shared tests cross-compile to Linux cleanly without undefined Windows `syscall` symbols.
- **Instrumented Event Queue Tests (`agent/internal/eventqueue/queue_test.go`)**: FIFO delivery, non-destructive $O(1)$ oldest event age, instrumented `Enqueue(ctx, ev)` API, exact adapter blocked enqueue attempts under capacity, multiple concurrent blocked producers, context cancellation unblocking, `TryEnqueue`, pressure episodes, bounded waiter admission queue memory limits with `ErrQueueAtCapacity`, clean drain of committed items with `ErrQueueClosed` for pending submissions on queue close, mixed channel/direct-API saturation preserving events without drop or premature termination, unblocking adapter and pending waiters on close while no consumer progresses without deadlock, preservation of adapter-held events during close without data loss, and concurrent senders under the 64-bit CGO race detector.
- **Ingestion-Outcome Reconciliation Tests (`agent/internal/ingestion/engine_test.go`)**: Deterministic accounting verification across committed, pre-commit failure, DLQ recovery, disk spill, and drop outcomes with zero count skew.
- **Queued Drain & Finalization Tests (`agent/internal/integration/queued_drain_report_test.go`)**: Production-path regression holding ingestion behind an explicit barrier, buffering events in memory, verifying actual measurement runner duration expiry, releasing barrier, executing shared `ExecuteShutdown`, and reconciling terminal durable outcomes; error capture testing confirming collector and forwarder stop failures modify report outcome; and simulated DB close failure verification asserting that `ExecuteShutdown` truthfully records `<OUTCOME>_WITH_ERRORS: storage close: ...` in the report on disk and returns an exit-failing error.
- **Native YARA-X Detection Workload Tests (`agent/internal/integration/workload_detection_yarax_test.go`)**: Direct comparative overhead benchmark linking against native `libyara_x_capi` (v1.20.0), measuring Nearest-Rank percentile latency (Min, Mean, P50, P90, P95, P99, Max) with separate scanner evaluation vs total finding persistence durations, Go heap memory, and storage amplification between harmless events and genuine positive detection matches with deep payload deserialization, deterministic UUIDv5 finding identity, exact causal linkage (`evidence_event_ids`), post-close reopen durability, and zero event loss under `-race`. Eliminates double scanning by separating pure rule scanner timing from pipeline ingestion timing, using `countingRuleWrapper` to strictly assert 1 evaluation per event in pipeline benchmarks. Pre- and post-collection boundary checks strictly enforce clean committed source (`dirty: false`) for qualification evidence; `ALLOW_DIRTY_EVIDENCE` is eliminated from the accepted evidence path, verified by `TestYaraX_QualificationEvidenceRefusesDirtyOverride_RetainsDiagnostics` which proves dirty checkouts refuse export, write 0 accepted evidence files, and retain diagnostics under `invalid_<runID>`. Replaced all discarded `FinalizeFailure` results with `failWithDiagnostics`, verified by `TestWorkload_YaraX_DiagnosticFinalizationFailure_PreservesBothCauses` proving both the workload failure cause and the diagnostic retention failure are visibly reported and exit code is nonzero. All assertions must pass before export. Exports typed machine-readable evidence (`YaraXComponentEvidence`) exclusively to `docs/evidence/phase4/runs/<runID>/yarax_component_evidence.json` with overwrite refusal and proven survival across staging cleanup (`TestWorkload_YaraX_ComponentEvidenceExport`).
- **Delivery Failure Boundary Integration Tests (`agent/internal/integration/delivery_boundaries_test.go`)**: Deterministic verification across 7 delivery boundaries and 4 OS process crash regressions: receiver unavailable, receiver reconnecting, upload timeout, duplicate ack/retry, graceful restart with pending events, storage transaction rollback, ack without durable receiver persistence, child-process abrupt termination via `cmd.Process.Kill()` (`TestCrashBoundary_SubprocessStorageCrash_ProcessTermination`, `TestCrashBoundary_SubprocessUncommittedDelete_ProcessTermination`, and `TestCrashBoundary_SubprocessForwarder_ProcessTermination`), and runaway noisy child subprocess bounding (`TestCrashBoundary_NoisyChildProcess_BoundedOutputAndReap`). All crash subprocesses are governed by `ManagedCrashProcess` with 20s execution deadlines, thread-safe bounded buffers (`boundedBuffer`, 64 KB limit), visible truncation markers (`[OUTPUT TRUNCATED]`), immediate cleanup registration, 5s reap deadlines, barrier write error checking, and exact recovery assertions. Explicitly distinguishes forced termination from cleanup failure without claiming physical power-loss durability.

## Known Testing Limitations
- Actual network partition simulation is limited to mock HTTP clients.
- File system space exhaustion is not reliably tested in CI.
- True concurrency testing is limited due to the intentional serialized SQLite access design in Alpha.
- Linux cross-compilation is verified (`GOOS=linux go test -c ./agent/internal/integration`), but runtime execution of Linux tests requires a real Linux environment (CI `ubuntu-latest`) and must not be inferred from local Windows test runs.
- Windows developer-host smoke-run evidence is developer-machine telemetry and does not substitute for low-spec hardware qualification.
