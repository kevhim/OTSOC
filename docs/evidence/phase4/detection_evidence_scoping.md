# Phase 4: Native Detection Evidence Scoping & Endpoint Rule Loading Blocker

## 1. Scope & Execution Boundary of Detection Evidence

The performance and durability evidence generated by `agent/internal/integration/workload_detection_yarax_test.go` exercises the native YARA-X detection engine as a **component-level integration test**.

### Measured Boundary
- **Included Paths**:
  - `detection.NewYaraRule`: Compiles native YARA-X rule text via CGO (`libyara_x_capi`).
  - `ingestion.Engine.ProcessEvent`: Event payload deserialization, device ID stamping, SQLite `events` insertion, and transaction commit.
  - `detection.Engine.Evaluate`: Rule evaluation (`YaraRule.Evaluate`), deterministic UUIDv5 finding generation, causal evidence linkage, and derived finding persistence into SQLite `events`.
  - Durability and reopen recovery: Verifies findings survive SQLite close and independent database reopen.
- **Excluded Paths (Bypassed Components)**:
  - OS-level collectors: Process monitor (`collectors/process`), Network socket collector (`collectors/network`), and File system change watcher (`collectors/filesystem`).
  - Input ingestion queue: Bounded event queue (`eventqueue.Queue`) and adapter wait paths.
  - Network forwarder: HTTP transport delivery to upstream API.

```
Component Integration Test Scope:
[Synthetic Event] -> [ingestion.Engine] -> [SQLite events (source)]
                              |
                              v (OnCommitted hook)
                     [detection.Engine]
                              |
                     [YaraRule.Evaluate] (libyara_x_capi)
                              | (Match)
                     [Derived Finding] -> [SQLite events (finding)]
```

This component-level isolation is critical for benchmarking the precise latency, memory, and storage amplification of rule execution and finding generation without collector scheduling jitter or queue saturation noise.

## 2. Production Endpoint Rule Loading Blocker

The endpoint binary compiled from `agent/cmd/endpoint/main.go` **cannot currently execute dynamic YARA-X detection rules**.

### Concrete Code Inspection
In `agent/cmd/endpoint/main.go` (lines 118–122):
```go
// Phase 3 Detection Core (Active Deterministic Rules)
activeRules := []detection.Rule{
    &detection.RealIOCExecRule{},
}
log.Printf("Production detection engine initialized with %d active deterministic rules", len(activeRules))
detEngine := detection.NewEngine(db, activeRules)
```

Furthermore, `agent/internal/config/config.go` defines the endpoint configuration structure:
```go
type Config struct {
    APIAddr           string   `json:"api_addr"`
    TenantID          string   `json:"tenant_id"`
    SiteID            string   `json:"site_id"`
    ProcessInterval   string   `json:"process_interval,omitempty"`
    InventoryInterval string   `json:"inventory_interval,omitempty"`
    NetworkInterval   string   `json:"network_interval,omitempty"`
    MonitorPaths      []string `json:"monitor_paths,omitempty"`
}
```

### Gap Analysis
1. **Hardcoded Rule Set**: Only `RealIOCExecRule` (a Go struct implementing `detection.Rule`) is loaded.
2. **Missing Configuration**: `Config` lacks a `rules_dir` parameter, preventing administrators from pointing the agent to a directory of `.yar` rule files.
3. **No Dynamic Compiler**: The binary has no initialization loop to scan a filesystem directory, compile `.yar` rule sources, and inject compiled `*detection.YaraRule` instances into `activeRules`.

Consequently, qualification runs executed against `endpoint.exe` only evaluate `RealIOCExecRule`; they do not exercise native YARA-X rules.

## 3. Smallest Required Design Change

To enable full end-to-end native YARA-X rule execution within the production `endpoint.exe` binary without architectural disruption, the following changes are required:

### A. Configuration Addition (`agent/internal/config/config.go`)
Add an optional `RulesDir` field:
```go
type Config struct {
    // ... existing fields ...
    RulesDir string `json:"rules_dir,omitempty"`
}
```
Optionally support a CLI flag `-rules-dir` in `agent/cmd/endpoint/main.go` that overrides the configuration file.

### B. Dynamic Rule Loader (`agent/cmd/endpoint/rules_loader_cgo.go`)
Under `//go:build cgo`, implement a loader function:
```go
func loadDynamicYaraRules(rulesDir string) ([]detection.Rule, error) {
    if rulesDir == "" {
        return nil, nil
    }
    entries, err := os.ReadDir(rulesDir)
    if err != nil {
        return nil, fmt.Errorf("failed to read rules dir %s: %w", rulesDir, err)
    }

    var compiledRules []detection.Rule
    for _, e := range entries {
        if e.IsDir() || (!strings.HasSuffix(e.Name(), ".yar") && !strings.HasSuffix(e.Name(), ".yara")) {
            continue
        }
        rulePath := filepath.Join(rulesDir, e.Name())
        ruleContent, err := os.ReadFile(rulePath)
        if err != nil {
            return nil, fmt.Errorf("failed to read rule %s: %w", rulePath, err)
        }
        ruleID := strings.TrimSuffix(e.Name(), filepath.Ext(e.Name()))
        yaraRule, err := detection.NewYaraRule(ruleID, string(ruleContent), ruleID, "1.0", "CRITICAL")
        if err != nil {
            return nil, fmt.Errorf("failed to compile YARA rule %s: %w", rulePath, err)
        }
        compiledRules = append(compiledRules, yaraRule)
    }
    return compiledRules, nil
}
```

### C. Stub Loader for Non-CGO Builds (`agent/cmd/endpoint/rules_loader_nocgo.go`)
Under `//go:build !cgo`:
```go
func loadDynamicYaraRules(rulesDir string) ([]detection.Rule, error) {
    if rulesDir != "" {
        log.Printf("WARNING: rules_dir specified (%s) but CGO is disabled; YARA-X rules will not be loaded", rulesDir)
    }
    return nil, nil
}
```

### D. Endpoint Wireup (`agent/cmd/endpoint/main.go`)
```go
dynamicRules, err := loadDynamicYaraRules(cfg.RulesDir)
if err != nil {
    log.Fatalf("Failed to load YARA detection rules: %v", err)
}
activeRules := append([]detection.Rule{&detection.RealIOCExecRule{}}, dynamicRules...)
```

### Summary of Scope
Until this design change is implemented and integrated into the endpoint binary, all native YARA-X qualification evidence remains scoped strictly to **component integration testing** (`agent/internal/integration/workload_detection_yarax_test.go`), while full-binary workload reports evaluate standard process/network collector activity with `RealIOCExecRule`.
